Bug 1: DataSerializer: Integer Truncation in upb_Decode due to casting size_t to int32_t causing Out-of-Bounds Read and SEGV

Vulnerability type: Memory Corruption

Details

Summary

An Integer Truncation/Overflow vulnerability (CWE-190) exists in the DataSerializer PHP extension (specifically within the underlying upb parsing library). When processing exceptionally large binary descriptor sets, the library fails to safely validate input lengths, leading to a critical Out-of-Bounds Read and a fatal process crash (Segmentation Fault).

Technical Details

When a large payload (e.g., 2GB or 2,147,483,648 bytes) is passed to Example\DataSerializer\DescriptorPool::internalAddGeneratedFile(), the execution flow moves deep into the native C layer:

  1. zim_DescriptorPool_internalAddGeneratedFile calls add_descriptor_set.
  2. It invokes example_dataserializer_FileDescriptorSet_parse which routes down to upb_Decode.
  3. Inside _upb_Decoder_DecodeMessage and its inlined fallback checks (_upb_Decoder_IsDoneFallback), the size parameter (originally a 64-bit size_t) is implicitly or explicitly cast/truncated into a signed 32-bit integer (int32_t).
  4. This truncation causes the massive positive boundary size to wrap around and be interpreted as a negative integer (-2147483648).
  5. Subsequent pointer arithmetic corrupted by this negative length value results in an invalid memory read access within __memcpy_aarch64_simd, triggering an immediate SIGSEGV.

Proof of Concept (PoC)

Run the following standard PHP command in an environment compiled with AddressSanitizer (ASAN):

php -d extension=dataserializer.so -r '$pool = Example\DataSerializer\DescriptorPool::getGeneratedPool();$pool->internalAddGeneratedFile(str_repeat("A", 2147483648));'

Attack scenario

Exploitation Vector & Attacker Capabilities

An attacker who can control or influence the binary descriptor data supplied to an application utilizing the DataSerializer PHP extension can exploit this vulnerability. This is especially critical in scenarios where applications accept untrusted or user-supplied protocol buffer configurations, schema uploads, or dynamic descriptor streams without strict upfront validation of the payload size at the application layer.

Core Security Impact

  • Remote Denial of Service (DoS): Because the error triggers a hard Segmentation Fault (SIGSEGV) directly at the native C library layer rather than throwing a catchable or loggable PHP exception, it completely terminates the entire executing process instantly.
  • Process Pool Exhaustion: In production web environments (such as PHP-FPM or Apache worker setups), repeatedly sending this payload will continuously crash and kill backend worker processes. This forces the server to constantly respawn processes, leading to resource exhaustion (CPU/Memory spikes) and rendering the web application or microservice completely unavailable to legitimate users.
  • System Instability: The reliability of the crash makes it highly trivial for an attacker to maintain a persistent state of Denial of Service, severely breaking service-level agreements (SLAs) and core system availability.
